# Rule changes need confirmation

- Before adding or changing a rule in the global rules (the common and host files in your global rules repo, and the language files) or in any project's CLAUDE.md/AGENTS.md, state my understanding in plain words. If it conflicts with another rule, say what it contradicts and what it adds, and reorder rules if needed.
- Then ask with exactly two options: Yes (add it as stated) or No (don't add it). To clarify or change it, answer through the free-text "Other" field; restate and ask again. Nothing is written until the answer is Yes. Lessons are exempt.
- Scope first: decide where a new rule belongs (global, host, language file, org, repo or memory) and name it when restating. A rule born from frustration with one project goes to that project.
