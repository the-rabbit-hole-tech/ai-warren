# Bug-report sessions

1. Listen and log first, to the bug log (the host file names its path), in the owner's words, with the repo and its place in the list. Don't fix or file anything while the owner is still reporting.
2. The order and priority come from how each message opens; don't re-rank them.
3. Then examine each entry: reproduce it, find the root cause, and map what it touches.
4. File or update one issue per entry, after searching for an existing one.
5. Present the waves for approval.

Features in a bug list are fixes: each takes its bug's priority, wave and place in the list, ahead of other open work, and still needs the owner's Yes as a feature PR before merging.
